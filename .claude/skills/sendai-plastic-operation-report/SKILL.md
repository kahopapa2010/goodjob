# 操業日報 → JUST.DB 移行（変換・検証・分析Excel）

## 何をするか
月次の操業日報Excel（1ファイル＝1か月）から、次の2つを作る。
- **03_移行用CSV/**：JUST.DBに取り込むCSV（マスタ、T01〜T12、T90）、旧日報の日別集計値のCSV、`00_移行手順と検証結果_YYYYMM.xlsx`
- **04_操業分析（CSV差し替え式）.xlsx**：JUST.DBから出力したCSVを貼り替えるだけで更新できる分析ブック。複数月を渡したときは全月分のデータが入る

テーブル設計は `references/tables.md` にある。旧Excelのセル配置と業務ルールは `references/excel-layout.md` にある。

## 手順
1. **出力先を決める。** 日報には実際の操業データ（重量、出荷先、トラブル）が入っている。
   このリポジトリは公開リポジトリなので、出力は**リポジトリの外**（スクラッチパッドなど）か、`.gitignore` 済みの `操業日報_JUSTDB移行/` に置く。**CSVやExcelは絶対にコミットしない。**
2. **変換を実行する。** 1か月あたり約2分かかる。複数月はCPU数まで並列で変換するので、1年分なら全月まとめて1回で渡す（4コアで約6〜8分）。タイムアウトを長めに取るか、バックグラウンドで実行する。
   ```bash
   python .claude/skills/sendai-plastic-operation-report/scripts/run_all.py <出力フォルダ> <日報1.xlsx> [<日報2.xlsx> ...]
   ```
   - `-j 1` を付けると1か月ずつ順に変換する（メモリが足りないとき）。
   - 月ごとのログは指定した順に表示される。M01〜M08 は最後に指定した月の内容になるので、**古い月→新しい月の順**に渡す。
   - 0件のテーブル（予定外休止がない月のT08など）も見出しだけのCSVが出る。
   - 中では次の3つが順に動く。1つずつ実行してもよい。
     - `extract.py <xlsx> <CSVフォルダ>`：T01〜T12を作る
     - `build_masters.py <xlsx> <CSVフォルダ>`：マスタ、T90、検証を作る
     - `build_analysis.py <CSVフォルダ> <出力.xlsx>`：分析Excelを作る
   - 月ごとの `OK`/`NG` 行が出力され、NGがあれば終了コードは1になる。
3. **検証結果を確認する。** 9項目すべてが `OK` になること。確認する項目は次のとおり。
   - 入荷の重量と個数
   - 処理の個数と重量
   - 減容品の重量と袋数
   - 製品出荷と廃棄物出荷
   - 実操業時間

   NGが出たら、その月のレイアウトが変わっている可能性が高い。`references/excel-layout.md` の行・列と実ファイルを見比べ、`extract.py` を直してから再実行する。**差を残したまま渡さない。**
4. **分析Excelを再計算して確認する。** xlsxスキルの `scripts/recalc.py` を使う（数式は約1000個、数秒で終わる）。
   `libreoffice-calc` が入っていないとタイムアウトするだけで終わるので、そのときは `apt-get install -y libreoffice-calc` を先に実行する。結果は次の2点を満たすこと。
   - `total_errors: 0`
   - 「ダッシュボード」の値が検証結果の合計と一致する（原料処理量(t)＝原料処理重量kg÷1000 など）
5. **報告する。** 次の4つを伝え、`run_all.py` が作った `<出力フォルダ>/操業日報_JUSTDB移行_YYYYMM.zip` をユーザーに送る（SendUserFile）。
   - **zip は `zip` コマンドで作り直さない。** ファイル名にUTF-8の目印が付かず、Windowsで開くとファイル名が文字化けする（2026年8月分で実際に起きた）。作り直すときは `scripts/make_zip.py <出力フォルダ>` を使う。
   - 月ごとの件数
   - 検証結果（全項目一致か）
   - ダッシュボードの主な数字（原料処理量、製品生産量、収率、処理ペース、予定外休止、トラブル件数）
   - 気づいた点。特に次のもの：
     - セル内の足し算による入力
     - `#REF!` になっている出荷先の見出し
     - 新しく出てきた品目や出荷先
     - 実績0の区分

## 注意
- **受け取ったファイルをそのまま使う。**
  - 他ファイル参照（前月ファイル、原料、直送計量など）の値は、ファイルに保存されている計算結果から読んでいる。
  - Excelや LibreOffice で開いて保存し直すと、その値が消える。
- 日報Excelの画像・グラフは読まない（`scripts/xlsx_load.py`）。2026年8月分に実体のない画像参照があり、そのままでは読み込みで止まったため。
- **M01〜M08 は全月共通**の1ファイルで、後から変換した月の内容で上書きされる。
  - 出荷先（M05）は出荷シートの見出しから作るので、月によって増えることがある。
  - 増えていたら報告する。
- **M09・T01〜T12・T90・検証CSV** はファイル名に `_YYYYMM` が付くので、月ごとに別ファイルになる。
- `build_analysis.py` は、CSVフォルダにある同じテーブルの全月分をまとめて取り込む。対象月の初期値は、データの最新月になる。
- 移行の進め方（体制、並行運用、切替など）を聞かれた場合は、リポジトリ直下の `操業日報_JUSTDB移行計画.pptx` の流れ（STEP 0〜7）に沿って答える。
